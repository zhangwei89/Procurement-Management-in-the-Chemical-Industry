# 第15章 人工智能产品与服务采购管理

## 章节导读

如果说传统的工业信息化软件（如 ERP、MES）是对确定性业务逻辑与物理流转的“结构化固化”，那么人工智能（Artificial Intelligence, AI）与大语言模型（LLM）的崛起，则正在为化工企业注入具有感知、推理、决策与自进化能力的“硅基智慧大脑”。从利用计算机视觉（CV）全天候识别工人未佩戴防化服、现场跑冒滴漏与违规动火，到运用大语言模型自动化审查上百页厚重的采购招标文件与技术协议；从基于图神经网络（GNN）预测分子逆合成路线，到利用强化学习智能体（AI Agent）在数万个工艺变量中实时寻找高压加氢反应釜的最优能耗操作点，人工智能技术正在全方位重构化工企业的生产力边界。

然而，对于企业采购人员而言，**人工智能产品与服务的采购，是一场彻底颠覆传统采办认知与商业契约框架的崭新战役**。传统软件采办的是“具有确定性输入输出的代码”（输入 A 必然得到 B）；而 AI 模型采办的是基于统计学与概率论的“非确定性黑盒能力”（存在不可预测的幻觉与漂移）；传统的计费模式是买断 License 或按人头订阅，而 AI 采办引入了每千 Token 计费、GPU 卡时计费、Prompt 缓存折让等极其复杂的“Token 算力经济学”；更令管理层心惊胆战的是，一旦在合同中缺乏严密的数据安全合规约束，企业耗费数十年积累的核心工艺配方、单耗参数与商业机密，极可能在调用公网 API 时被模型提供商悄然抓取回传用于基础模型再训练，造成毁灭性的商业机密泄漏灾难。

采购人员如何从“买确定性软件”跨越到“买概率性智能服务”？通用大模型、垂直行业大模型与专用小模型该如何权衡选型？公网 API、本地私有化量化部署与专属算力集群租用的经济学平衡点何在？如何构建防范模型幻觉的基准测试集（Benchmark）？如何设计数据版权、免责兜底与人机协同（Human-in-the-loop）的商业合同？本章将系统揭密化工行业人工智能采办的全新技术体系、商业规则与法律风控实务。

## 15.2 模型形态分类采办：通用基座模型、行业垂直模型与专用小模型

在启动 AI 项目采办时，盲目迷信“模型参数越大越好”是典型的外行误区。超大模型不仅推理成本昂贵、响应时延漫长，而且在很多专业化工物理计算上往往不如经过专门蒸馏优化的垂直小模型。

```
┌────────────────────────────────────────────────────────────────────────┐
│                   化工企业 AI 模型采办“三层金字塔架构”                │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
    ┌───────────────────────────────┼───────────────────────────────┐
    ▼                               ▼                               ▼
【第一层：通用基座大模型】      【第二层：化工行业垂直模型】    【第三层：专用端侧小模型】
· 百亿/千亿参数密集/MoE模型     · 在基座模型上注入化学分子知识、· 几千万至数亿参数专用模型
· 擅长通用语言理解、逻辑推理、  热力学机理、安全法规深度微调    · 工业计算机视觉(CV)缺陷检测、
· 文档摘要、商务跨语种翻译      · 擅长反应路线推演、配方筛选    · 跑冒滴漏识别、阀门仪表自诊断

```

### 15.2.1 三类模型的采办选型决策准绳

| 模型形态分类 | 算力消耗与成本 | 擅长业务场景 | 采购决策建议 |
| :--- | :---: | :--- | :--- |
| **通用基座大模型** | 高 (调用公网API或多卡并行) | 采购技术文件初审、法律合同漏洞扫描、跨语种海外供应商沟通、会议纪要自动归纳 | 采用**公网 API 按量付费**，或租用公有云大模型平台，配置多模型路由机制，避免独家绑定 |
| **化工垂直行业大模型** | 中 (需8卡/16卡GPU私有化微调) | 催化剂分子筛选逆合成预测、复杂工艺操作规程（SOP）智能问答、生产调度方案辅助决策 | **私有化本地部署为主**，采购模型代码与权重，联合科研院所或行业领军AI企业进行知识库微调（RAG） |
| **专用工控小模型** | 极低 (单块轻量化边缘芯片) | 厂区人员未戴安全帽识别、动火作业明火烟雾侦测、皮带机跑偏与法兰微量泄漏识别 | **软硬一体开箱即用采办**，采购工业防爆边缘计算一体机，按摄像头接入路数打包结算 |

## 15.4 算力与服务模式：公网 API、本地私有化与专属算力集群租用

算力与部署模式的选择，是决定 AI 项目投资规模与安全防线的最大分水岭。

```
┌────────────────────────────────────────────────────────────────────────┐
│                   AI 三大算力与服务部署模式技术经济对比                │
└──────────────────┬─────────────────┬───────────────────────────────────┘
                   │                 │
                   ▼                 ▼
         【模式 A：公网 API Token 调用】   【模式 B：本地私有化推理部署】
         (Public Cloud API)                (On-Premises Deployment)
         ───────────────────────────────── ─────────────────────────────────
         · 零初期算力硬件 CAPEX 投资       · 初期需采购昂贵 GPU 服务器 (CAPEX)
         · 按实际使用的 Token 数量付费     · 模型权重与企业数据完全不出厂区机房
         · 模型能力最强，自动享受原厂迭代  · 算力固定，存在硬件折旧与电费成本
         · 【痛点】：存在工业数据泄密顾虑  · 【优势】：本质数据安全，网络零延迟
                                     │
                                     ▼

                           (Dedicated Cloud GPU Cluster)
                           在公有云租用带物理隔离的独立 GPU 裸金属算力服务器,
                           按月或按年支付租金；兼具弹性与相对数据隔离度
```

### 15.4.1 三大部署模式的决策量化模型

$$\text{当月度调用 Token 数量 } T_{\text{month}} > T_{\text{breakeven}} \text{ 时，私有化部署成本将显著低于公网 API}$$

- **盈亏平衡点推演**：若企业调用频次极高（如全厂上万个摄像头 24 小时不间断进行视觉分析，或企业数千名员工每日高频进行智能交互），公网 API 的月度按量账单将迅速膨胀为天文数字；此时**采购本地 GPU 服务器进行模型量化（INT8/INT4量化）私有化部署，其 1~2 年的硬件投资回报率（ROI）将远超公网调用**；
- 反之，如果企业仅用于偶尔的招标文档辅助审查或管理层决策咨询，**坚决推行公网 API 调用，避免数百万硬件资产闲置折旧**。

## 15.8 化工场景基准测试集（Benchmark）构建与盲测盲评机制

在采购招标时，绝对不能让供应商用他们自己准备的“展示用 PPT 或预设 Demo”进行演示。因为供应商会针对特定 Demo 进行精巧的过拟合刷题作弊。

### 15.8.1 构建业主专有的“封闭盲测题库”（Blind Benchmark）
企业采购部必须协同工艺、安环、法律部门，在招标前秘密构建一套包含 **300~500 道真实化工工业题目的封闭测试集**：
1. **安全规程与危化品应急库**：设计刁钻问题，如*“储罐区发生氢氟酸微量泄漏且伴随周边变压器火灾，第一响应人应选择何种灭火与防护介质？”*，考核模型是否会给出“用水灭火导致酸液飞溅”的致命错误回答；
2. **非标招标文件合规审查题库**：人为在 10 份历史招标文件中植入隐蔽的排他性品牌参数、违规账期条款，考核大模型能否 100% 自动抓取识别；
3. **盲测盲评打分（Double-Blind Evaluation）**：开标现场，在统一的隔离内网环境下，将题库同时推送给各投标供应商的模型，隐去供应商名称，由 5 名内部专家与资深算法工程师进行背靠背盲审打分。

## 15.13 工业机密与数据安全：严禁未经脱敏的核心配方回传

在化工行业，核心工艺催化剂的摩尔配比、特种助剂的反应温控曲线，是企业投入数代研发人员、耗费数亿元资金沉淀出的**最高商业机密（Trade Secrets）**。

### 15.13.1 设立数据出厂前的“本地脱敏过滤网关”
凡是需要调用外部公网大模型 API 的业务场景，必须在内网出口处部署**“AI 本地数据安全网关（Data Sanitization Gateway）”**：
- **敏感实体自动脱敏**：网关自动运用命名实体识别（NER），将文本中出现的具体装置位号、真实化学品专有代号、真实供应商名称、实际生产吨位数字，自动替换为泛化占位符（如将“在 3 号高压反应釜注入 2.5 吨 MDI”自动替换为“在 [装置A] 注入 [物料X]”）；
- 模型返回处理结果后，网关在企业内网本地进行逆向映射还原，确保**“真正高敏的商业核心数据物理不出厂区”**。

## 本章实战案例：大模型 API 费用超支惊魂与招标文件审查幻觉复盘

### 案例背景
华东某百亿级化工新材料集团积极推进数字化与 AI 赋能，2023 年底立项启动了“企业级智能采购助手与工艺知识问答平台”。项目由某知名 AI 创业团队 J 公司承建，采用公网顶级商业大模型 API 驱动。

### 危机爆发一：令人目瞪口呆的“Token 账单失控惊魂”
项目上线试运行仅第 2 个月，集团财务部突然收到了服务商寄来的一张令人倒吸一口凉气的公网 API 账单：
- **账单金额**：原本预算仅规划为 2 万元/月的大模型 API 调用费，当月账单竟然高达 **48.6 万元人民币（超支近 25 倍！）**；
- **排查真相**：
  1. 工程师在编排工作流时设计严重失误：为了让模型理解上下文，居然将包含数百页的整本《全厂化工装置大修安全技术规程》完整 PDF 全文（高达 20 万 Token），每次都机械地拼接在每一个普通员工的每一个简单提问前面重复发送；
  2. 未开启服务商提供的“Prompt 上下文缓存（Prompt Caching）”功能，每一次调用都按全量输入计费；
  3. 系统缺乏并发调用配额与熔断机制，车间个别年轻工程师利用企业内部账号，调用该大模型进行私人海量代码编写与长篇小说生成，导致在短短 10 天内无序消耗了数亿 Token！

### 危机爆发二：模型严重幻觉漏判排他壁垒引发招标巨震
如果说费用超支只是财务上的破财，那么随之而来的一起**“AI 模型幻觉引发的招标严重事故”**，则直接将集团推到了法律诉讼的悬崖边缘：
- **事故回溯**：
  在某套新建万吨级催化剂装置核心超高温耐酸换热器的公开招标中，采购经办人员由于轻信了该 AI 系统的“招标文件智能合规审查”功能，直接将技术部门报送的 150 页《技术规格书》交由大模型进行自动审查；
- **致命的幻觉与遗漏**：
  大模型给出了清晰明了的审查报告：*“经审查，本技术文件合规，未发现任何违反《招标投标法》的排他性倾向条款，建议发布”*；采购员未加细致人工复核，直接盖章发布了公开招标文件；
- **恶果引爆**：
  招标文件发出仅 3 天，国内 4 家顶尖换热器制造龙头联合向当地国资委与招投标监管部门提交了实名举报信与长达 20 页的投诉函！
  原来，在技术规格书的第 89 页一个极其不起眼的脚注里，技术部隐蔽地植入了欧洲某特定厂商独家专有的**“三维螺旋波纹管专利流道几何曲率参数代码（精准到小数点后四位）”**，客观上直接锁死了只有该欧洲厂商一家能够响应投标，构成了名副其实的排他性量身定制！
  大模型在进行长文本推理时发生了严重的**“中间丢失与注意力幻觉（Lost in the Middle）”**，漏判了这个关键致命参数；
  该事故导致整座重大建设项目的招标进程被监管部门紧急叫停整顿，企业面临信誉受损与行政处罚风险。

### 痛定思痛的体系化重塑与治理
这两起触目惊心的事故，彻底击碎了企业管理层对 AI 技术的盲目乐观，促成了集团对 AI 采购与运行机制的深刻重塑：
1. **建立算法工程层面的“Token 熔断与多级缓存体系”**：
   - 彻底重构 RAG 知识检索架构：严禁整本长文档粗暴拼接，必须通过语义切片（Chunking）与向量相似度检索，精准提取最相关的 3~5 个段落送入大模型，**单次调用的输入 Token 数量断崖式骤降 92%**；
   - 强制开启 Prompt Caching 上下文缓存，对高频复用的标准规程实施缓存折价；在每个业务部门设立月度 Token 硬性预算配额，超额自动切断；
   - 次月整顿后，全集团大模型 API 月度费用直接从 48.6 万元暴降并稳定在 **1.5 万元以内**！
2. **构筑“人机协同（Human-in-the-loop）”铁律红线**：
   - 确立制度红线：**“AI 审查结果仅视为初筛参考意见，绝不能替代法定专业工程师的人工签字把关！”**；
   - 研发针对招投标场景专用的“细粒度排他性规则校验引擎”，并强制推行“AI 预审出具疑点清单 $\rightarrow$ 专职技术审查工程师对疑点逐条人工复核销号 $\rightarrow$ 采购经理终审”的三级闭环审查流；
3. **合同条款重构与索赔**：
   - 依据合同中关于算法服务商技术瑕疵的条款，向集成商 J 公司追究责任，从其项目尾款中直接扣除了 15 万元作为算法失误的违约赔偿；
   - 这一场惊魂复盘，让该化工集团成为国内工业领域最早建立起专业、严谨、抗脆弱的 AI 治理与采办管理体系的标杆企业。

## 本章小结与管理工具箱

### 核心认知总结
1. AI 采办是概率性智能服务的采办，采购人员必须跳出买确定性传统软件的旧思维；
2. 坚决摒弃模型唯大论，大模型负责语义理解与复杂逻辑，专用小模型负责高帧率边缘感知，追求最优性价比；
3. 谨慎权衡公网 API、私有化部署与专属算力集群的经济平衡点，根据业务调用频次选择最优部署模式；
4. 建立企业专有封闭测试集（Benchmark）实施盲测盲评，彻底识破厂商的过拟合营销套路；
5. 推进 Prompt 资产与底层模型解耦，部署多模型网关，坚决规避单一技术锁定（Vendor Lock-in）；
6. 守牢工业机密与核心工艺配方数据出厂的安全红线，部署本地数据脱敏网关；
7. 恪守人机协同（Human-in-the-loop）底线，高危工况严禁赋予算法直接物理控制权；
8. 严防 Token 经济学中的费用暴击，工程上推行 RAG 语义切片、Prompt 缓存与模型路由。
